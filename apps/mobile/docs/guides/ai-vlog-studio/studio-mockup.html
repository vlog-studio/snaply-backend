스튜디오 — 작업대형

전제: 사용자는 결과물을 자기 손으로 통제하고 싶어한다. AI는 주인공이 아니라 마지막에 붙는 강력한 도구다. 홈은 “내 작업대” — 담아둔 재료와 진행 중인 무비가 항상 여기 놓여 있고, 앱을 다시 열면 하던 작업을 이어서 한다.

세 방향(오늘 / 스튜디오 / 레시피)을 비교해 이 방향으로 확정했다. 기획 전문은 concept.md. 이 목업은 확정된 화면과 플로우를 눌러볼 수 있게 만든 것이고, 데이터는 전부 가짜다. 아직 src에는 반영되지 않았다.

탭 구성

스튜디오·스냅·● 촬영·무비·나

핵심 발명은 “담기 트레이”다. 스냅 탭에서 고른 스냅은 곧바로 무비가 되지 않고 스튜디오의 트레이에 쌓인다 — 장바구니처럼. 여러 날에 걸쳐 재료를 모을 수 있다.

무비를 만드는 경로

스냅→선택 → 담기→스튜디오 트레이→새 무비 시작
편집기①조립(순서·길이)②스타일·음악③AI 생성

초안은 언제든 저장되고, 스튜디오 보드에서 이어서 작업할 수 있다.

이 방향을 고른 이유

  • “내가 만들었다”는 소유감이 가장 강하다 — 공유 동기가 붙는다.
  • AI 결과가 마음에 안 들 때 사용자가 고칠 손잡이가 있다.
  • 트레이 덕분에 여러 날짜에 걸친 무비를 자연스럽게 만든다.
  • 콜드 스타트에 강하다 — 스냅 0개여도 홈이 “뭘 하면 되는지” 말한다.
  • 운영 비용이 0에 가깝다 — 백엔드는 합성 잡 하나로 출발할 수 있다.

감수하는 것

  • 단계가 많다. 첫 무비까지 탭 6–8번 — 이탈 지점이 많다.
  • AI가 “도구”로 밀려나서 제품 차별점이 흐려질 수 있다. 차별화는 트레이와 재료 관리 경험이 진다.
  • 트레이라는 개념을 사용자가 학습해야 한다 — 온보딩 한 장이 필요하다.

폐기한 두 방향은 뒤 단계로 밀어뒀다 — 제안 카드는 v1.2에 스튜디오 상단으로, 레시피는 카탈로그를 운영할 사람이 생기면 v1.3으로.

백엔드에 필요한 것

  • 초안 저장 — PATCH /movies/:id로 순서·트림·스타일을 서버에 유지(기기 교체 대응).
  • 합성 잡 — 사용자가 정한 순서/트림을 그대로 지키는 모드가 필요. AI가 순서를 다시 짜면 안 된다.
  • 무비 완성 푸시 — 합성이 40초씩 걸리면 사용자는 앱을 나간다. 기존 FCM 인프라 재사용.
  • 스타일/BGM 카탈로그 API.
