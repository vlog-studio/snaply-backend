## 1. SNS 연동 (TikTok · Instagram)

**공유된 사실**
- 두 플랫폼 연동은 **테스트 계정**으로 개발했고, 영상 업로드를 포함해 정상 동작을 확인했다.
- 웹훅을 연동하려면 **HTTPS 고정 도메인**이 필요하다. **사내 AWS 등록 현황을 파악해 도메인을
  추가**하기로 했다.

**현행 문서와의 관계**
- "정상 동작 확인"은 [specs/sns-sharing.md](../specs/sns-sharing.md) SNS-5(인스타 릴스 실게시)와
  일치한다. 틱톡은 여전히 받은함 방식이고(SNS-6), **받은함 실물 도착**(backlog C-2)이 이 회의에서
  확인된 것인지는 메모에 없다 — 확인됐다면 C-2 를 닫고 [progress.md](../progress.md)에 기록한다.
- 고정 도메인은 backlog **D-1** 이 원천이다. 기존 D-1 은 Cloudflare 보유 도메인을 전제했으므로,
  사내 AWS 도메인으로 가면 `dev-tunnel.sh`(cloudflared named tunnel) 경로 대신 운영 배포(B-1)
  경로에서 해결된다. 이 판단을 D-1 에 덧붙였다.

## 2. BGM · 자막

| 안건 | 결과 |
|---|---|
| BGM | **AI 생성 음원 사용** 제안. 법적 정책(생성 음원의 상업 이용·소셜 업로드 허용·저작권 귀속)을 **먼저 확인한 뒤 결정** |
| 자막 | **미정** |

**현행 문서와의 관계**
- BGM 조달은 backlog **A-7** "BGM 조달 경로와 예산" 항목이다. 상업 라이선스 3사 비교에 **AI 생성**
  선택지를 추가했다. A-7 이 요구하는 조건(최종 사용자의 소셜 업로드 허용 · Content ID 클레임 면제 ·
  만료 무비 무료 재생성을 위한 영구 사용권)은 AI 생성 음원에도 그대로 적용된다.
- 자막은 현행 스펙 MOV-9(opt-in 소프트 자막)가 구현된 상태이고, 번인 전환 여부가 A-7 의 미결이다.
  회의에서도 결론이 없었으므로 A-7 미결이 그대로 유지된다.

## 3. 프로젝트 → 영상 → 내보내기 동선 · 에셋

- **동선**: 프로젝트 → 영상 → 목록 → 내보내기까지 **바로 이어지게** 한다.
- **스티커·에셋 확보**가 필요하다. 이를 위해 **관리자 페이지 도입**(에셋 관리 기능 등)이 필요하다.

**현행 문서와의 관계**
- 스티커 에셋 확보·라이선스·매니페스트 스키마는 A-7 에 이미 있다. **관리자 페이지(에셋 관리)**는
  새 항목이라 A-7 에 추가했다. 관리자 인증·권한 모델이 없으므로 착수 전 결정 문서가 필요하다.

## 4. 영상 · 프로젝트 · vlog 개념 정리 (제안)

회의에서 정리한 세 층의 개념이다. **현행 용어와 매핑**: 아래 `video` = 현행 **스냅(Snap)**,
`project` = 현행 **무비(Movie)**, `vlog` = 현행 **렌더 결과물(EditJob 출력)**.

| 층 | 회의 내용 | 현행 스펙 |
|---|---|---|
| video | 15일 지속. 기존 스냅 개념(3~5초 촬영) 또는 사용자 영상에서 추출. **서버 업로드 성공 시 로컬 삭제** | 스냅은 기기 라이브러리에 보관되고 서버는 백업(SNAP-6~8). 기간 만료 개념 없음 |
| project | 구성 요소: video · order · effect · sticker(?) · bgm · subtitle. video 를 합쳐 준다(내보내기). **임시저장(미리보기 — 부자연스러운 전환 보강 필요)** · **내보내기 완료 시 프로젝트 삭제** | 무비 = 스냅 컷 목록 + 스타일(MOV-1). 초안 편집·재생성 지원(MOV-4). 생성 구성은 영구 보관(MOV-14) |
| vlog | project 의 내보내기 결과물. 내보내기 화면에서 **다운로드 / 연동(SNS) 선택** → 진행하면 **삭제** | 결과물 서버 보관 30일 + 만료 후 무료 재생성(MOV-16, `결정·미구현`) |

**⚠️ 현행 결정과 충돌하는 지점** — 확정하려면 spec 을 먼저 고치고 결정 문서에 기각안을 남겨야 한다
([AGENTS.md](../../AGENTS.md) §문서 갱신 의무):

1. **video 15일 지속 · 업로드 후 로컬 삭제** — 스냅을 기기 원천에서 서버 원천으로 옮기는 변경이며
   [decisions/snap-source-of-truth.md](../decisions/snap-source-of-truth.md)의 단계 계획과 맞물린다.
   15일 만료는 무료 2GB 보관 한도(SNAP-9)와 어떤 관계인지(만료가 한도를 대체하는지, 병행인지) 정해야 한다.
2. **내보내기 완료 시 프로젝트 삭제 · 결과물 진행 후 삭제** — MOV-14(구성 영구 보관)·MOV-16(30일
   보관 + 무료 재생성)과 정면으로 충돌한다. 삭제로 가면 "만료 무비 무료 재생성" 약속과 A-7 의
   영구 라이선스 조항 논의(에셋 만료 시 재생성 보장)가 필요 없어지므로, 이 결정은 A-1 · A-2(보관 축
   구독) · A-7 세 항목에 동시에 영향을 준다.
3. **미리보기(임시저장)** — 현행은 서버 생성 결과만 볼 수 있다. 전환 품질을 보강한 앱 측 미리보기는
   앱 기능 문서([apps/mobile/docs/features/movie.md](../../apps/mobile/docs/features/movie.md)) 갱신 대상이다.

이 세 가지를 backlog A-1 "남은 판단"에 한 항목으로 묶어 올렸다.

## 5. 그 밖의 확인·검토 항목

- **AI 추천 프로젝트** — 좀 더 고민이 필요하다. 템플릿 기반 추천(A-6)이 이미 구현·비활성 상태이므로
  "프로젝트 자동 구성 추천"이 A-6 의 확장인지 별개 기능인지부터 정한다.
- **영상 업로드 시 위치 정보** — 필요하겠지만 안 될 수도 있다. 서버 저장은 SNAP-11 `보류`이고
  A-4 의 프라이버시·약관 검토가 선행이다. 이 회의로 바뀐 것은 없다.
- **프로젝트 내보내기 시 영상의 구간을 따로 받는지** — 확인 필요로 남겼다. 현행 스펙으로는
  **이미 지원한다**: MOV-1 은 같은 스냅을 다른 구간으로 여러 번 쓸 수 있다고 하고, MOV-7 은 각 컷을
  트림 구간대로 자른다. 계약의 실제 필드명은 [api-spec.md](../api-spec.md) 편집 작업 절과
  [packages/shared-types/src/contract/](../../packages/shared-types/src/contract/)에서 확인한다.
