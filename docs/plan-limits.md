# 제한 정책 현황 — 기능적 제한 vs 플랜(수익화) 제한

> 2026-08-05, Dev A. 플랜별 제한의 기획이 확정되지 않아 **월 3편 제한을 로직에서 임시 제외**하면서,
> 현재 시스템의 제한이 각각 어떤 성격인지, 재도입 시 무엇을 결정해야 하는지 정리한 문서.
> 관련 코드 위치와 논의 배경 포함. 기획 확정 후 이 문서를 기준으로 재구현한다.

---

## 1. 기능적/기술적 제한 (플랜과 무관 — 유지)

시스템 보호용이라 유료 플랜에도 그대로 적용된다. 값 조정은 가능하되 없앨 성격이 아니다.

| 제한 | 값 | 초과 시 | 위치 | 이유 |
|---|---|---|---|---|
| 요청당 클립 수 | `videoIds` 1~10개 | 400 | `routes/edit-jobs.ts` 스키마 | 클립 수만큼 정규화 인코딩·crossfade 필터가 늘어나 워커 점유 시간 상한 필요 |
| 업로드 크기 | 클립당 500MB | 400 (`POST /videos` 시점) | `storage.service.ts` (`S3_MAX_UPLOAD_BYTES`) | presigned PUT은 발급 시 크기 제한 불가 → 등록 단계에서 HEAD 검사 |
| 편집 요청 빈도 | 토큰당 5회/분 | 429 `RATE_LIMITED` | `routes/edit-jobs.ts` rateLimit | 요청당 비용이 큰 작업이라 큐 폭탄 방지 |
| 전역 요청 빈도 | IP당 60회/분 | 429 | `app.ts` (P9) | 일반 API 남용 방지 |
| geofence 알림 | 토큰당 10회/분 | 429 | `routes/notifications.ts` |〃 (B 트랙) |
| 워커 타임아웃 | job당 10분 | `failed` 처리 | `worker.py` `asyncio.wait_for` | 행 걸린 ffmpeg/whisper가 워커를 영구 점유하는 것 방지 |
| 소유권/상태 | 내 소유 + `ready`만 편집 가능 | 403 | `edit-job.service.ts` | 데이터 무결성 |

## 2. 플랜(수익화) 제한 — **전부 미적용 상태**

> ⚠️ 2026-08-11 업데이트: 스토리지 용량 한도(Free 5GB)가 별도 결정됨 —
> [snap-source-of-truth.md](./snap-source-of-truth.md) §6 참조. 또한 무비 생성 과금은
> 아래 "월 3편" 모델 대신 **크레딧 기반 결제**로 재설계 예정(미구현)이라, 이 표의
> 편집 횟수 항목은 크레딧 기획 확정 시 대체될 수 있다.

기획 정의(가이드 §Phase 8, `billing.service.ts`의 `features` 문구):

| | Free (₩0) | Standard (₩9,900) | Premium (₩24,900) |
|---|---|---|---|
| 편집 횟수 | 월 3편 | 무제한 | 무제한 |
| 해상도 | 720p | 1080p | 4K |
| 워터마크 | 강제 삽입 | 없음 | 없음 + 추가 기능 |

구현 상태:

- **월 3편**: 구현되어 있었으나 **2026-08-05 임시 제거** (아래 §3). 이력은 git에 있음
  (`edit-job.service.ts`의 `FREE_MONTHLY_LIMIT`, 제거 커밋 참조).
- **해상도 차등**: 미구현. 워커가 플랜과 무관하게 1080x1920으로 렌더링. 큐 페이로드에
  plan이 전달되지 않아 워커는 요청자 플랜을 알 수 없다.
- **워터마크**: 미구현 (같은 이유).
- `GET /billing/plans`의 `features` 배열은 FE 표시용 문구일 뿐 백엔드가 집행하지 않는다.
  ⚠️ 현재 이 문구는 실제 동작과 불일치 (월 3편도 미적용) — 기획 확정 시 B 트랙과 함께 갱신.

## 3. 월 3편 제한을 임시 제거한 이유

- 해상도/워터마크가 미구현이라 어차피 **플랜 차등이 일관되게 동작하지 않는 상태**였음.
- 결제(B 트랙)와 편집 엔진(A 트랙)에 걸친 기획이라 각자 부분 구현하면 어긋남.
- 기존 구현에 기획 판단이 필요한 논점들이 있었음 (§4). 어설픈 정책으로 개발·검증만
  방해(실검증 중 반복 403)되어, 기획 확정까지 제외하기로 결정.

## 4. 재도입 시 결정해야 할 것 (기획 논점)

기존 구현(`git log -S FREE_MONTHLY_LIMIT`)의 동작과 논점:

1. **차감 시점** — 기존: `edit_jobs` 레코드 생성 시점 카운트. 그래서 **실패한 편집도
   차감**됐다 (워커 버그로 3회 실패하면 그 달 편집 불가). 성공 시점 차감으로 바꾸면
   사용자에게 유리하지만, 고의 취소/타임아웃 어뷰징 여지. → 절충안: `status != 'failed'`
   만 카운트 or 실패 시 환급.
2. **리셋 기준** — 기존: **UTC 월초** (`Date.UTC(y, m, 1)`) = 한국 시간 매월 1일 09:00.
   KST 자정으로 할지, 가입일 기준 rolling 30일로 할지.
3. **"1편"의 정의** — 기존: `POST /edit-jobs` 1회 = 1편 (클립 1개든 10개든 동일).
   클립 수·영상 길이 가중치를 둘지.
4. **해상도 차등과 세로 규격의 충돌** — 2026-08-04에 출력이 세로 1080x1920으로 확정됨.
   "Free 720p"를 세로로 해석하면 720x1280인지, 단변 720 기준인지 정의 필요.
5. **워터마크 스펙** — 위치/크기/로고 에셋. `editor.py`에 overlay 한 단계 추가로 구현 가능.
6. **전달 경로** — 해상도/워터마크를 강제하려면 큐 페이로드(`EditJobData`)에 plan을 실어
   워커에 전달해야 한다 (`subtitles` 옵션과 같은 패턴, 2026-08-04 커밋 참조).
