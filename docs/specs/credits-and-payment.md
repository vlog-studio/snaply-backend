# 스펙 — 크레딧과 결제

**작성일**: 2026-09-02

## 과금 모델

- **CRD-1** `구현됨` — 과금 단위는 크레딧이고, **무비 생성 1회 = 100크레딧**이다.
  이 단위는 바꾸지 않는다 — 바꾸면 이미 지급된 잔액 전부를 리스케일해야 한다.
  100 단위인 이유는 광고 보상·보너스처럼 지급 사유가 늘 때 정수로 조절하기 위해서다.
- **CRD-2** `구현됨` — **정기 구독으로 생성 권한을 팔지 않는다.** 생성은 크레딧, 보관은 구독
  (CRD-7)으로 축을 분리하고, **구독은 크레딧을 지급하지 않는다** — 두 축을 섞는 상품은
  검토 대상이 아니다.
- **CRD-3** `구현됨` — 잔액과 사용 가능 여부의 **원천은 항상 백엔드**다. 앱·결제 SDK 의
  상태는 표시·동기화용이다. 사용자는 잔액과 최근 사용 내역(지급·차감 사유 포함)을
  볼 수 있다.

## 크레딧 판매 (인앱결제)

- **CRD-4** `구현됨`(백엔드) / 스토어 등록은 `결정·미구현` — 크레딧은 앱 내 인앱결제
  (Apple/Google, RevenueCat 경유)로만 판다. 가격 표시의 원천은 스토어다.
  팩 구성(500/1,200/3,000)은 잠정값이며 스토어 미등록 상태다([backlog.md](../backlog.md) A-2·C-1).
- **CRD-5** `구현됨` — 지급은 멱등하다: 같은 거래가 여러 번 통지돼도 한 번만 지급하고,
  앱의 유실 보정 동기화를 몇 번 호출해도 잔액이 중복 증가하지 않는다.
- **CRD-6** `구현됨` — 스토어 환불은 지급분을 회수한다. 이미 쓴 크레딧 때문에 잔액이
  **음수가 될 수 있으며**, 음수 잔액은 신규 생성만 막고 기존 결과물은 회수하지 않는다.
- **CRD-7** `결정·미구현` — 스냅 보관 한도 확장은 **자동 갱신 구독**으로 판다. 용량 티어·
  가격·연 구독 여부는 미결이다([backlog.md](../backlog.md) A-2).
- **CRD-8** `구현됨` — 가입 보너스는 현재 **0**(지급 안 함)이다. 수량은 정책 값으로 언제든
  켤 수 있다.

## 보상형 광고

정책 값의 배경: [decisions/ad-reward-credits.md](../decisions/ad-reward-credits.md) §7

- **ADR-1** `구현됨` — 사용자는 보상형 광고를 끝까지 보고 크레딧을 받을 수 있다:
  **1회 20크레딧, 하루 5회, 쿨다운 300초.** 한도를 다 쓰면 정확히 무비 1편(100크레딧)이
  되지만, **"광고 5편 = 무비 1편"으로 묶어 표시하지 않는다.**
- **ADR-2** `구현됨` — 지급의 유일한 트리거는 **광고 플랫폼의 서버 측 검증 콜백**이다.
  앱은 지급을 요청할 수 없고, 지급량도 앱이 정하지 않는다(세션 발급 시점에 서버가 확정).
  서명·시각·세션·사용자·광고 단위·한도·계정 상태를 전부 통과해야 지급한다.
- **ADR-3** `구현됨` — 한도는 **실제 지급 횟수**로만 센다. 광고를 끝까지 못 봤거나 콜백이
  유실된 시도는 한도를 깎지 않는다. 광고가 성립하지 않으면 앱이 세션을 포기해 즉시 다음
  기회를 얻는다.
- **ADR-4** `구현됨` — 보상량·한도·쿨다운·버튼 노출 여부의 원천은 서버 응답이다. 앱은 이
  값을 하드코딩하지 않으며, 킬 스위치로 진입점 자체를 숨길 수 있다.
- **ADR-5** `구현됨`(코드) / 실지급은 외부 승인 대기 — 광고 지급 전 구간은 구현·테스트가
  끝났으나, 스토어 미출시로 광고 플랫폼(AdMob) 검토를 통과할 수 없어 실제 지급은 아직
  일어나지 않는다([backlog.md](../backlog.md) C-6). 그때까지 기능은 꺼져 있다.
- **ADR-6** `구현됨` — 정책 값의 불변 관계 두 가지는 테스트로 고정한다:
  `보상량 × 일일 한도 = 생성 1회(100)`, `세션 TTL ≤ 쿨다운`.
