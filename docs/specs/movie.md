# 스펙 — 무비 구성과 AI 생성

**작성일**: 2026-09-02
**상태**: 현행 — 무비 요구사항의 원천
**관련 문서**: [decisions/movie-model.md](../decisions/movie-model.md) · [decisions/movie-cleanup-after-export.md](../decisions/movie-cleanup-after-export.md) · [decisions/auto-edit-draft.md](../decisions/auto-edit-draft.md) · [apps/mobile/docs/features/movie.md](../../apps/mobile/docs/features/movie.md) · 표기 규칙은 [README.md](README.md)

## 무비 모델

- **MOV-1** `구현됨` — 무비는 **스냅 컷 목록 + 스타일**이다. 스냅은 평면으로 보관되고 무비가
  참조한다 — 같은 스냅을 여러 무비가, 같은 스냅을 한 무비 안에서 다른 구간으로 여러 번 쓸 수 있다.
- **MOV-2** `구현됨`(실기기 미검증 — [backlog.md](../backlog.md) A-1) — 무비는 **서버가 소유**한다. 기기를
  바꾸거나 앱을 지워도 무비는 돌아온다. 앱이 서버 무비를 기기에 두는 방식은
  [decisions/movie-client-cache.md](../decisions/movie-client-cache.md). 무비는 스냅을 **참조**할 뿐이라
  한 스냅을 여러 무비가 다르게 쓰고, 무비를 지워도 스냅은 남는다.
- **MOV-3** `구현됨` — 무비를 시작하는 경로는 두 가지고 같은 화면에서 만난다:
  스냅을 직접 골라 시작하거나, 템플릿으로 시작한다([template-and-recommendation.md](template-and-recommendation.md)).
  고른 스냅으로 AI 편집 초안을 받는 세 번째 경로는 MOV-21 이다(`부분` — 실기기 확인 전).

## 초안 편집

- **MOV-4** `구현됨` — **모든 편집은 생성 밖에서 일어난다.** 초안에서 컷 순서 변경·삭제·트림·
  추가·스타일 변경을 마친 뒤 생성을 시작하고, 결과물도 같은 화면·같은 컨트롤로 고쳐서
  다시 생성한다. 생성 중(`generating`)인 무비만 잠긴다.
  **끝낸(MOV-17) 무비도 같은 화면에서 계속 편집할 수 있다** — 사라지는 것은 결과물 파일이지
  프로젝트가 아니다.
- **MOV-5** `구현됨` — 무비 하나의 컷은 **최소 1개, 최대 10개**다.
- **MOV-6** `구현됨` — 스타일 프리셋은 `감성`·`여행`·`일상` 세 가지다. 프리셋은 색보정과
  **AI 가 고르는 전환의 경향**을 정한다 — 일상은 바로 넘기고, 감성은 겹쳐 녹이고, 여행은 빠르게 끊는다.
  촬영 시각이 30분 이상 떨어진 경계는 스타일과 무관하게 장면 전환으로 넘긴다. 규칙은
  [decisions/transition-director.md](../decisions/transition-director.md), 경계마다 바꾸는 것은 MOV-22 다.

## AI 편집 초안

- **MOV-21** `부분`(2026-10-01 — 서버 제안 API 와 앱의 진입·흐름까지 구현했고 Android 에뮬레이터에서 확인했다. 실기기에서 결과물이 편집 화면과 같은지와 거르기 문턱값 실측이 빠졌다) — 사용자가 넘긴 **스냅 여러 개**(촬영했거나 가져온 스냅)로 AI 가
  **고칠 수 있는 무비 초안**을 만든다. AI 는 쓸 스냅을 고르고(못 쓰는 것·중복은 뺀다), 순서를 정하고,
  컷마다 구간을 자르고, 컷 사이 전환을 고른다. 결과는 렌더된 영상이 아니라 일반 무비 초안이며,
  사용자는 보고 고친 뒤 생성한다(MOV-7). 초안을 받는 데는 **크레딧을 쓰지 않는다.** 컷 수는 MOV-5 를
  따른다. 사용자가 분석에 동의하지 않았거나 분석이 꺼져 있어도 초안은 만들어진다 — 분석은 초안을 낫게 할
  뿐 조건이 아니다(REC-4·ANA-5). 근거는 [decisions/auto-edit-draft.md](../decisions/auto-edit-draft.md) §5.
  - 한 번에 넘길 수 있는 스냅은 **최대 30개**, 초안은 **최근 24시간에 10번**까지다. 넘으면 서버가 거절한다.
    초안 1회가 vision 분석에 보내는 스냅은 **최대 12개**다(잠정값 — 단가 실측 A-3 뒤 다시 정한다).
  - 초안은 **기다리지 않고 바로** 나온다. vision 분석 결과는 나중에 도착하면 사용자가 손대지 않은 값에만 얹는다.
  - **업로드가 끝나지 않은 스냅도 넣는다.** 빼거나 구간을 고르지 않고 촬영 순서 자리에 둔다.
  - 넣지 않은 스냅이 있으면 **개수를 알리고, 그 스냅을 다시 넣을 수 있게** 한다. 이유는 보여주지 않는다.
  - AI 가 자른 구간도 사용자가 고치면 그 뒤로 사용자 것이다(MOV-22).
- **MOV-22** `구현됨`(2026-10-01, Galaxy 실기기에서 미리보기와 결과물의 경계 일치 확인) — 초안에서 AI 가 정한 값은 **전부** 사용자가 고칠 수 있다. 지금의 편집(MOV-4)에
  더해 **컷 사이 전환을 경계마다** 바꿀 수 있고, 경계마다 고를 수 있는 전환은 편집 화면에서 미리 볼 수
  있어야 한다. 사용자가 고친 값(순서·구간·전환)은 AI 가 초안을 다시 만들어도 덮지 않는다.
  이 규칙은 AI 초안뿐 아니라 **모든 무비**에 적용된다 — 직접 스냅을 고른 무비도 경계마다 AI 가 고른
  전환으로 시작한다.
  - 경계마다 전환은 **AI 가 고른 것이거나 사용자가 고른 것**이고, 어느 쪽인지 무비에 남는다. AI 가 고른
    경계는 컷이나 스타일이 바뀔 때 AI 가 다시 고르고, 사용자는 경계 하나를 다시 AI 에게 맡길 수 있다.
  - 컷마다 구간도 **AI 가 자른 것이거나 사용자가 자른 것**이고, 어느 쪽인지 무비에 남는다. AI 가 구간을 자르는 것은
    초안(MOV-21)뿐이다 — 직접 스냅을 고른 무비와 이 규칙 전에 만든 무비의 구간(스냅 전체 포함)은 사용자 것이다.
    AI 가 자른 구간을 사용자가 고치면 그 뒤로 사용자 것이고, 사용자 구간은 AI 가 바꾸지 않는다.
  - 사용자가 고른 전환은 **그 두 컷이 이어져 있는 동안** 유지된다. 순서를 바꾸거나 컷을 빼서 두 컷이
    떨어지면 그 경계는 AI 가 다시 고른다.
  - 전환이 컷에 들어가지 않을 만큼 컷이 짧거나 원본에 여분 프레임이 없으면 그 경계는 전환이 짧아진다.
    겹쳐 녹이기가 들어가지 않으면 검게 넘기기로, 그마저 안 되면 바로 넘어간다 — 트림하지 않은 컷은 여분이
    없어 대개 검게 넘기기가 된다. 고른 값은 그대로 남아 트림으로 여분이 생기면 돌아온다. 전환의 종류·길이 범위는
    [`transition-vocabulary.json`](../../packages/shared-types/src/transition-vocabulary.json)이 원천이다.
  - 겹쳐 녹이는 전환도 컷 구간 밖의 여분 프레임을 쓰므로, 사용자가 자른 구간은 전부 보이고 무비 길이는
    컷 길이의 합이다.

## 생성 (AI 편집)

- **MOV-7** `구현됨` — 생성은 **백엔드의 실제 작업**이다: 각 컷을 트림 구간대로 자르고,
  스타일로 색보정하고, 분위기에 맞는 음악을 입히고, (선택 시) 자막을 넣어 하나의 영상으로
  렌더링한다. 화면 이탈·백그라운드·강제 종료에도 작업은 계속된다.
- **MOV-8** `구현됨` — 기본 출력은 **세로 1080×1920 숏폼**이다. 가로·정사각 등 다른 출력
  프로필과 화면 맞춤 방식(잘라 채움/여백/블러 배경)을 고를 수 있다. 비율이 다른 원본도
  결과물에서 깨지지 않는다.
- **MOV-9** `구현됨` — 자막은 **opt-in** 이다(기본 없음). 켜면 한국어 음성 인식으로 소프트
  자막이 들어간다 — 플레이어에서 켜야 보이며, SNS 업로드 시 유실될 수 있음을 안내한다.
- **MOV-10** `구현됨` — 생성 1회는 **크레딧 100을 예약**한다. 잔액이 모자라면 작업이 아예
  시작되지 않고 필요량·잔액을 안내한다. 실패하거나 취소되면 예약분은 **전액 자동 환급**되며,
  자동 재시도로 추가 차감되지 않는다.
- **MOV-11** `구현됨` — 진행률은 실시간으로 표시되고, 사용자는 진행 중 작업을 **취소**할 수
  있다. 사용자당 진행 중 생성은 **한 번에 1개**다(앱이 강제).
- **MOV-12** `구현됨` — 실패는 사용자가 이해할 수 있는 분류(시간 초과·원본 없음·서버 오류 등)로
  전달되고, 원문 진단 메시지는 사용자에게 노출하지 않는다. 실패한 무비는 어느 화면에서든
  재시도할 수 있다.
- **MOV-13** `구현됨` — 모든 생성은 동일 조건이다 — 해상도·워터마크의 유료 차등이 없다.
- **MOV-14** `부분` — 생성에 쓰인 구성(편집 스펙·렌더 스펙)은 영구 보관되어, 같은 구성을
  다시 실행하면 같은 결과가 나와야 한다. **단, 원본 스냅이 남아 있는 동안만이다** — 스냅은
  15일이면 만료되고(SNAP-9) 컷이 하나라도 만료되면 그 구성은 다시 실행할 수 없다(MOV-20).
  예외를 두지 않기로 한 근거는
  [decisions/movie-snap-expiry-exemption.md](../decisions/movie-snap-expiry-exemption.md).
  재현성을 깨는 또 하나는 BGM 무작위 선택이다([backlog.md](../backlog.md) E-5 — A-7 의 `bgm_tracks` 와 함께 닫는다).
- **MOV-20** `구현됨` — 만료·삭제된 스냅을 쓰는 컷이 있으면 **생성이 400 으로 막힌다.** 무비 자체는
  열리고 그 컷은 `unavailable` 로 보이며, 사용자가 그 컷을 빼면 다시 생성할 수 있다.

## 결과물 보관과 공유

- **MOV-15** `구현됨` — 완성 무비는 같은 화면에서 재생되고, 이름을 바꿀 수 있으며,
  **공유**는 렌더된 파일을 받아 시스템 공유 시트로 넘긴다.
  이 감상 화면은 **완성 시점부터 끝내기(MOV-17) 전까지**만 존재한다 — 끝낸 무비를 열면
  결과물이 없으므로 편집 화면으로 연다.
- **MOV-16** `구현됨` — **끝내지 않은** 결과물의 서버 보관 상한은 **30일**이다. 사용자가
  끝내지 않고 방치한 경우에도 파일이 무한히 남지 않게 하는 상한이며, 끝내면 그보다 먼저
  사라진다(MOV-17). 만료 안내를 어떤 알림으로 줄지는 미결이다([backlog.md](../backlog.md) A-1).
  ※ 종전의 "만료된 무비를 크레딧 없이 무료 재생성"은 **폐기됐다** — 다시 만들기는 항상 새 생성이다(MOV-19).
- **MOV-17** `구현됨`(실기기 미검증 — [backlog.md](../backlog.md) A-1) — 사용자가 결과물을 **다운로드하거나 SNS 에 게시해 "끝내면"**,
  서버의 결과물 파일을 삭제한다. **끝낸 브이로그는 다시 볼 수 없다** — 다시 보기 기능은 제공하지
  않는다. 남는 것은 프로젝트(구성)이며, 편집 화면에서 고쳐 다시 만들 수 있다
  ([decisions/movie-cleanup-after-export.md](../decisions/movie-cleanup-after-export.md), 2026-09-09 결정).
  화면에서는 이 동작을 `정리하기`라고 부른다 — "서버"는 사용자 용어가 아니다.
- **MOV-18** `구현됨` — **끝났다는 판정은 추측하지 않는다.** 앱은 공유 시트가 올라온 뒤에도 "저장했나요?"
  확인을 받아서만 끝내기를 부른다. 시스템 공유 시트는 사용자가 실제로
  저장했는지 알려주지 않으므로(시트를 닫기만 해도 성공과 구분되지 않는다), 다운로드 경로의 끝내기는
  **사용자의 명시적 행동**이어야 한다. SNS 게시는 서버가 성공을 알고 있으므로 자동으로 판정한다.
- **MOV-19** `구현됨` — 끝낸 뒤 다시 만드는 것은 **새 생성**이며 **크레딧 100 을 다시 낸다.**
  사용자가 이미 결과물을 가져갔기 때문이다.
