# 스냅의 사용자 사본 — 앨범 저장과 "이 기기에서만 삭제"

## 무엇을 정했나

| # | 질문 | 결정 |
|---|---|---|
| ① | 서버가 스냅을 영구 보관하지 않는데, 사용자는 스냅을 어떻게 계속 갖는가 | **기기 앨범에 저장한다.** 스냅마다 하나씩 저장할 수 있고, 찍을 때마다 저장하는 **자동 앨범 저장**을 둔다 |
| ② | 자동 앨범 저장의 기본값 | **꺼짐.** 나 탭에서 켠다 |
| ③ | 삭제할 때 서버 사본도 지울지 묻는가 | **묻는다.** 보관 중인 스냅은 **이 기기에서만 삭제**와 **모든 기기에서 삭제** 중에서 고른다 |
| ④ | 이 기기에서만 삭제한 스냅은 이 기기에서 어떻게 보이는가 | **목록에 남고 파일만 지운다.** 볼 때 보관 사본을 받아 재생하고 무비에도 계속 쓰며, 보관 기간이 끝나면 "만료됨"으로 남는다 |

## 왜 정해야 했나

스냅의 서버 보관은 업로드 후 15일이다([snap-retention-period.md](./snap-retention-period.md)). 지금은 촬영한 기기의 파일이
원천이라(SNAP-14) 그 파일이 있는 한 스냅은 남는다. 그런데 녹화 파일은 앱 전용 폴더에만 있고 기기 앨범에는 없다. 그래서
사용자가 앱 밖에 가진 사본이 하나도 없고, 아래의 경우 스냅은 되돌릴 수 없게 사라진다.

| 경우 | 결과 |
|---|---|
| 앱 삭제 · 기기 분실이나 교체 | 올린 지 15일 안이면 재설치로 돌아오지만 원본이 아니라 캐시의 배포본으로 돌아오고, 보관 기간이 끝나면 그것도 지워진다 |
| 다른 기기에서 본 스냅 | 보관 기간이 끝나면 그 기기에서 사라진다(촬영한 기기에만 남는다) |
| 계정 삭제 | 유예 30일이 지나면 앱이 기기의 스냅도 지운다 |
| 로컬 캐시 전환(SNAP-14)을 켠 뒤 | 서버 만료가 곧 완전 소멸이 된다([local-copy-after-upload.md](./local-copy-after-upload.md) §15일 만료와의 관계) |

서버를 영구 보관으로 바꾸지 않는 한 답은 사용자에게 사본을 주는 것이다. 같은 자리에서 "이 기기에서만 제거"도 다시 열렸다.
[snap-sync-across-devices.md](./snap-sync-across-devices.md)는 그것을 "두지 않은 것"으로 남기며, 기기 파일이 원천인 동안
촬영한 기기에서 제거하면 원본을 지우는 것과 같다는 이유를 댔다. 삭제할 때 서버 사본을 남길지 사용자에게 묻는다면 이 결과를
사용자가 알고 고르게 된다.

## 검토한 선택지

### ① 사용자가 사본을 갖는 방법

| 안 | 결과 |
|---|---|
| **A 앨범에 하나씩 저장 — 채택** | 서버 원칙을 지키면서 사용자가 소유하는 사본이 생긴다. 앨범의 사본은 앱을 지워도 남고, 사용자가 켜 둔 사진 백업(Google 포토·iCloud 사진)이 있으면 기기를 잃어도 남는다 |
| **C 자동 앨범 저장 — 채택(②의 기본값으로)** | 찍을 때마다 앨범에도 저장해, 사용자가 잊어도 사본이 생긴다. 로컬 캐시 전환(SNAP-14)을 켤 때 안전장치가 된다 |
| B 만료 전에 저장 유도(곧 끝나는 스냅 모아보기 · 예고 푸시 연결) | 이번에는 두지 않았다. 저장 경로(A·C)가 먼저다. 다른 기기에서 온 스냅은 만료되면 받을 파일이 없어 만료 전에만 저장할 수 있으므로 필요성은 남는다 — [backlog.md](../backlog.md) A-4 |
| D 유료로 보관 기간 연장 | 구조는 준비돼 있다(`retention-policy.ts`, `EXPIRY_TO_PURGE_DAYS`). 요금제 결정(A-2)의 몫이라 여기서 다루지 않는다 |
| 공유 시트로 내보내기 | 기각. 한 번에 파일 하나이고, 시트는 사용자가 실제로 저장했는지 알려주지 않는다(MOV-18 과 같은 한계) |
| 재설치 때 원본을 받아 기기 원천으로 되돌리기 | 기각. 올린 지 15일 안에만 의미가 있어 근본적인 해결이 아니다 |
| OS 백업에 맡기기 | 기각. Android 앱 자동 백업은 앱당 25MB라 영상이 들어가지 않고, iOS 기기 백업은 앱을 지우면 소용이 없다 |
| 배포본이나 썸네일만 영구 보관 | 기각. "서버는 스냅을 영구 보관하지 않는다"는 원칙과 충돌한다 |

### ② 자동 앨범 저장의 기본값

| 안 | 결과 |
|---|---|
| **꺼짐 — 채택** | 사용자가 원할 때 켠다. 권한이 필요한 기기에서도 첫 촬영을 권한 질문이 가로막지 않는다 |
| 켜짐 | 사용자가 모르는 사이 월 50편(약 300MB)의 3초 클립이 갤러리에 쌓인다. 기기 파일이 원천인 동안에는 같은 영상이 두 번 공간을 쓴다 |

### ④ 이 기기에서만 삭제한 스냅의 모습

| 안 | 결과 |
|---|---|
| **A 목록에 남기고 파일만 지운다 — 채택** | 공간만 비우고 스냅은 계속 쓴다. 모든 기기가 같은 목록을 본다는 원칙([snap-sync-across-devices.md](./snap-sync-across-devices.md) ①)이 그대로다. Google 포토의 "기기에서 삭제"와 같은 모양이다 |
| B 이 기기 목록에서 없앤다 | 기기마다 목록이 달라지고, 이 기기에서는 다시 볼 방법이 없다. 무비 컷은 라이브러리의 스냅을 찾아 그리므로 숨긴 기록을 따로 들고 있어야 컷이 깨지지 않는다. 사용자가 한 기기만 쓰면 남긴 보관 사본을 볼 곳이 없다 |

## 설계

### 앨범 저장

- **저장 위치.** Android 는 `Pictures/Snaply` 폴더(갤러리의 `Snaply` 앨범)다. iOS 는 앨범 없이 사진 보관함에 넣는다. iOS 에서
  앨범을 만들려면 사진 전체 접근이 필요한데, 추가만 하는 권한으로 충분한 일에 사용자의 사진을 읽는 권한을 받지 않기 위해서다.
- **권한.** 앨범에 **추가하는 권한만** 쓴다. Android 11 이상은 앱이 앨범에 파일을 넣는 데 권한이 필요 없어 묻지 않고, Android 10
  이하만 저장소 쓰기 권한을 묻는다. iOS 는 "추가만" 권한을 묻는다. 읽기 권한(`READ_MEDIA_*`)은 매니페스트에 들이지 않는다 —
  `expo-media-library` 는 기본값으로 이를 넣는데, 넣은 채로 올리면 Google Play 사진·동영상 권한 정책의 선언 대상이 될 수 있다.
  설정 플러그인에 `granularPermissions: []` 를 주고 모듈이 자체 매니페스트로 넣는 `READ_MEDIA_VISUAL_USER_SELECTED` 는
  `android.blockedPermissions` 로 뺀다.
- **무엇을 저장하나.** 이 기기에서 찍은 스냅은 원본을, 파일이 없는 스냅은 보관 사본(어디서나 재생되는 배포본)을 저장한다.
  아이폰 HEVC/HDR 원본은 Android 에서 재생되지 않을 수 있고 전송량도 약 두 배라 배포본을 받는다([snap-sync-across-devices.md](./snap-sync-across-devices.md) T4 와 같은 이유).
- **자동 저장의 대상.** 앱에서 찍은 스냅만이다. 갤러리 영상에서 가져온 스냅은 원래 영상이 이미 앨범에 있다.
- **실패.** 앨범 저장이 실패해도 스냅 저장은 성공으로 끝난다. 사본은 덤이지 스냅의 조건이 아니기 때문이다. 대신 저장하지
  못했다고 알린다 — 사용자가 사본이 있다고 믿고 앱을 지우면 안 된다.
- **저장했는지 기록하지 않는다.** 사용자가 갤러리에서 사본을 지워도 앱은 알 수 없으므로(읽기 권한이 없다), "저장됨" 표시는
  사실이 아닐 수 있다. 저장 직후 결과만 알린다.

### 이 기기에서만 삭제

- **대상.** 이 기기의 파일이 원본이고(`origin` 없음) 업로드가 끝났으며(`uploaded`) 보관 기간이 남은 스냅이다. 아직 올라가지
  않은 스냅과 보관 기간이 끝난 스냅은 파일이 이 기기에만 있고, 다른 기기에서 온 스냅은 이미 보관 사본을 보는 것이라 고를 것이 없다.
- **스냅의 id 는 그대로 둔다.** 파일을 지운 스냅은 다른 기기에서 온 스냅과 같은 상태(`origin: 'server'`, 파일 경로는 보관 사본을
  받아 둘 캐시)가 되지만 id 는 녹화 파일 이름 그대로다. id 를 서버의 `videoId` 로 바꾸면 무비의 컷 참조와 동기화 기록을 모두
  새 id 로 다시 써야 하고, 그 사이 서버에서 읽어 온 무비가 옛 id 로 컷을 가리키는 경합이 생긴다. id 를 두면 무비와 동기화는 아무것도
  바뀌지 않는다. 대신 보관 사본을 받을 때 `videoId` 는 동기화 기록에서 찾는다.
- **무비는 건드리지 않는다.** 스냅이 서버와 다른 기기에 그대로 있으므로 컷도 그대로다. 모든 기기에서 삭제만 컷을 뺀다(SNAP-5).
- **순서.** 파일을 먼저 지우고, 지워진 것만 목록에 반영한다. 파일 삭제가 실패할 수 있는 단계이고, 실패하면 스냅은 그대로다
  (`delete-snap` 의 모든 기기에서 삭제와 같은 규칙). 썸네일은 새 파일 경로의 이름으로 옮겨, 목록의 표지가 보관 사본을 받기 전에도 보이게 한다.
- **보관 기간이 끝나면** 다른 기기에서 온 스냅과 같다 — 받아 둔 사본을 지우고 "만료됨"으로 남는다(SNAP-12).

### 기존 결정과의 관계

- [snap-sync-across-devices.md](./snap-sync-across-devices.md) "두지 않은 것"의 **이 기기에서만 제거**를 들인다. 결정 ①(다른
  기기에서 지운 스냅은 이 기기의 원본까지 지운다)은 **모든 기기에서 삭제**의 규칙으로 그대로다.
- [local-copy-after-upload.md](./local-copy-after-upload.md)의 조건부 연기는 그대로다. 앱이 **스스로** 기기의 파일을 지우는
  전환은 여전히 조건이 충족된 뒤다. 이번에 들인 것은 사용자가 결과를 알고 고르는 삭제뿐이다.
