## 한 줄 요약

지금 "모든 기기에서 삭제"는 서버 파일과 **모든 기기의 원본 파일**을 즉시 지운다. 실수로 한 번 누르면 어느 기기에서도
되돌릴 수 없다. 휴지통을 두기로는 이미 정했으니, **얼마나 남겨 두고, 무엇을 되살리고, 어디서 되살리는지**를 정해야 한다.

## 지금 어떻게 동작하나

- `DELETE /videos/{id}` 는 그 영상이 가진 S3 객체(원본 · 배포본 · 썸네일)를 **곧바로 지우고** 행에 `deletedAt` 과
  `removalReason: 'user'` 를 남긴다(`video.service.ts` `deleteVideo`). 행은 툼스톤으로 남지만 되살릴 파일이 없다.
- 지운 기기는 그 스냅을 쓰던 무비에서 컷을 뺀다(SNAP-5). 확인 시트가 줄어드는 무비를 미리 보여 준다.
- 다른 기기는 다음 동기화에서 그 스냅을 목록에서 빼고 **자기 원본 파일까지 지운다**
  ([snap-sync-across-devices.md](./snap-sync-across-devices.md) ① A — "실수 삭제를 되돌리는 것은 휴지통의 몫"으로 남겼다).
- 확인 문구가 그 사실을 말한다: "모든 기기에서 파일까지 삭제되고, 되돌릴 수 없어요."(SNAP-16)
- 아직 올라가지 않은 스냅, 보관 기간이 끝난 스냅은 서버에 파일이 없어 삭제가 하나뿐이다(SNAP-19).

## 이 결정이 영향을 주는 곳

| 곳 | 무엇이 바뀌나 |
|---|---|
| 스펙 | SNAP-16 의 "되돌릴 수 없다" 와 확인 문구. 휴지통 요구를 새로 적는다 |
| 서버 | 삭제가 객체를 남긴다 · 되살리기 API · 유예가 끝난 객체를 지우는 정리(지금의 만료 정리 배치에 더할 수 있다) · `POST /videos/lookup` 이 "휴지통에 있음"을 구분 |
| 앱 | 확인 시트 문구 · 되살리는 곳(아래 ⑤) · 다른 기기의 동기화가 되살아난 스냅을 다시 들이는 경로(지금 다른 기기에서 온 스냅을 들이는 경로와 같다) |
| 비용 | 유예 동안 스냅당 약 9MB(원본 6 · 배포본 3 · 썸네일)를 더 든다. 보관 기간 상한(15일) 안이라면 지금 보관 원가를 넘지 않는다 |
| 법률 문서 | "보관 및 파기"에 삭제 후 유예를 적어야 한다(D-2 의 스냅 보관 기간 항목과 같은 자리) |

## 정할 것과 선택지

### ① 얼마나 남겨 두나

| 선택지 | 결과 |
|---|---|
| A 고정 N일(예: 7일) | 사용자가 기억하기 쉽다. 그러나 업로드 14일째 지운 스냅은 보관 기간(15일)을 넘겨 남는다 — 휴지통이 만료를 미루는 길이 된다 |
| B 30일 — 계정 삭제와 같게 | 규칙이 하나로 맞는다. A 보다 더 길게 만료를 넘긴다. "지워 두면 오래 남는다"가 보관 수단이 된다([movie-snap-expiry-exemption.md](./movie-snap-expiry-exemption.md) B 를 기각한 것과 같은 이유) |
| **C 원래 보관 기간이 끝날 때까지** | 따로 정하는 숫자가 없다 — 지운 스냅은 지우지 않았으면 남았을 때까지(업로드 후 15일) 되살릴 수 있다. 만료를 미루지 않는다. 늦게 지운 스냅일수록 짧다(14일째 지우면 하루) |
| D 고정 N일, 단 보관 기간이 먼저 끝나면 그때까지 | A 의 기억하기 쉬움과 C 의 만료 상한을 합친다. 숫자를 하나 정해야 한다 |

### ② 무엇을 되살리나

| 선택지 | 결과 |
|---|---|
| **A 스냅만** | 지울 때 무비에서 빠진 컷은 돌아오지 않는다. 되살린 스냅은 다시 넣으면 된다. 지운 뒤 무비가 바뀌었어도 충돌이 없다 |
| B 스냅과 무비의 컷 | 지울 때 어느 무비의 몇 번째였는지를 남겨야 하고, 그 사이 무비가 바뀌었으면 어디로 돌아갈지 정해야 한다. 생성 중이거나 끝낸 무비는 고칠 수도 없다 |

### ③ 휴지통에 있는 동안 다른 기기의 원본 파일은

| 선택지 | 결과 |
|---|---|
| **A 지금처럼 지운다** | 서버가 올라간 원본 그대로를 가지고 있어 되살리면 그 사본을 받는다. 기기마다 휴지통을 둘 필요가 없다. 되살린 뒤 처음 재생은 받아야 하므로 느리다 |
| B 유예가 끝날 때까지 숨겨 둔다 | 되살리면 바로 재생된다. 대신 기기마다 휴지통 상태를 들고, 되살리기 · 유예 만료를 기기마다 맞춰야 한다. 공간이 늦게 비워진다 |

### ④ 서버 사본이 없는 스냅(아직 안 올라감 · 보관 기간 끝남)은

| 선택지 | 결과 |
|---|---|
| **A 휴지통 대상이 아니다** | 지금처럼 바로 지우고 확인 문구가 "되돌릴 수 없어요"라고 말한다. 서버 휴지통 하나로 끝난다 |
| B 기기 휴지통을 따로 둔다 | 모든 스냅을 되살릴 수 있다. 기기 파일을 유예 동안 남기는 저장 · 정리 · 화면이 기기에 따로 생긴다 |

### ⑤ 어디서 되살리나

| 선택지 | 결과 |
|---|---|
| A 스냅 탭의 "최근 삭제" 모아보기 | 나중에 후회한 삭제와 다른 기기에서 한 삭제까지 되살린다. 화면이 하나 는다 |
| B 삭제 직후 "되돌리기"만 | 잘못 누른 직후만 잡는다. 다른 기기에서 지운 것, 조금 뒤에 알아챈 것은 못 잡는다 |
| **C 둘 다** | 서버 휴지통이 있으면 B 는 되살리기 호출 하나라 더하는 비용이 작다 |

## 권장

**① C · ② A · ③ A · ④ A · ⑤ C.** 서버에 파일이 남아 있는 동안만 되살린다는 규칙 하나로 정리된다 — 서버 휴지통 하나,
새로 정할 숫자 없음, 만료를 미루는 길 없음. 확인 시트는 "되돌릴 수 없어요" 대신 되살릴 수 있는 날짜를 말한다
("10월 14일까지 최근 삭제에서 되살릴 수 있어요"). 서버 사본이 없는 스냅만 지금 문구를 유지한다.

함께 따라오는 것(선택지가 아니라 결과):

- 휴지통의 스냅에는 만료 예고(D-3 · D-1)를 보내지 않는다 — 사용자가 이미 지웠다.
- 휴지통의 스냅은 목록 · 무비 · 추천 · 편집 초안 어디에도 나오지 않는다. 지금의 삭제와 같다.
- 계정을 지우면 휴지통도 계정과 함께 정리된다(계정 삭제의 30일 유예를 따른다).
