# 플랜 제한 집행 보류 결정

**작성일**: 2026-08-05 (2026-08-11 갱신)
**상태**: 대체됨 — 플랜 차등 집행 보류 후 정기 구독을 제거했다.
**범위**: 플랜 차등 집행 보류와 기존 월 3편 제한을 복원하지 않는 근거를 기록한다.
**원천**: 이 결정을 대체하는 새 정책이 나오기 전까지 플랜 제한 집행 여부의 원천이다.
**후속 작업의 원천**: [backlog.md](../backlog.md) A-2

> 2026-08-12 [credit-payment-model.md](./credit-payment-model.md)가 이 결정을 대체했다.
> 아래 내용은 구독형 플랜을 보류했던 시점의 근거로만 보존한다. 현행 결제 정책으로 사용하지 않는다.

플랜별 제한이 확정되지 않은 상태에서 부분 구현이 서로 어긋나는 문제를 막기 위해
기존 월 3편 제한을 제거했다. 기능적·기술적 보호 제한은 유지하고, 편집 횟수·해상도·
워터마크 같은 수익화 차등은 새 정책을 한 번에 결정하고 구현할 때까지 집행하지 않는다.
다른 곳(api-spec, `billing.service.ts`의 `features` 문구, 앱 화면)이 이 결정과 다르게 말하면
그쪽이 낡은 것이다.

---

## 0. 결정 요약

1. 기능적·기술적 보호 제한은 플랜과 무관하게 유지한다.
2. 기존 월 3편 제한은 제거하고 기계적으로 복원하지 않는다.
3. 편집 횟수·해상도·워터마크 등 플랜 차등은 새 수익화 정책이 확정될 때까지 집행하지 않는다.
4. Free 스토리지 5GB 정책은 별도 결정인 [snap-source-of-truth.md](./snap-source-of-truth.md)를 따른다.
5. 새 플랜 정책의 결정·구현 상태는 이 문서가 아니라 [backlog.md](../backlog.md) A-2에서만 관리한다.

### 결정 시점의 집행 상태 (2026-08-11)

| 제한 | 상태 |
|---|---|
| 기능적/기술적 제한 (§1) | **집행 중** — 플랜과 무관 |
| 편집 횟수 제한 | **집행하지 않음** — 월 3편 모델 제거(§3) |
| 해상도 차등 · 워터마크 | **미구현** |
| 스토리지 용량 한도 (Free 5GB) | **정책 결정됨, 미구현** — [snap-source-of-truth.md](./snap-source-of-truth.md) §6 |
| `GET /billing/plans` 의 `features` 문구 | FE 표시용 문구일 뿐 **백엔드가 집행하지 않음**. 현재 실동작과 불일치 |

즉 **지금 유료 플랜을 결제해도 무료 플랜과 기능 차이가 없다.** 이 상태를 전제로 개발·검증한다.

## 1. 기능적/기술적 제한 (플랜과 무관 — 유지)

시스템 보호용이라 유료 플랜에도 그대로 적용된다. 값 조정은 가능하되 없앨 성격이 아니다.

| 제한 | 값 | 초과 시 | 위치 | 이유 |
|---|---|---|---|---|
| 요청당 클립 수 | `videoIds` 1~10개 | 400 | `routes/edit-jobs.ts` 스키마 | 클립 수만큼 정규화 인코딩·crossfade 필터가 늘어나 워커 점유 시간 상한 필요 |
| 업로드 크기 | 클립당 500MB | 400 (`POST /videos` 시점) | `storage.service.ts` (`S3_MAX_UPLOAD_BYTES`) | presigned PUT은 발급 시 크기 제한 불가 → 등록 단계에서 HEAD 검사 |
| 편집 요청 빈도 | 토큰당 5회/분 | 429 `RATE_LIMITED` | `routes/edit-jobs.ts` rateLimit | 요청당 비용이 큰 작업이라 큐 폭탄 방지 |
| 전역 요청 빈도 | IP당 60회/분 | 429 | `app.ts` (P9) | 일반 API 남용 방지 |
| geofence 알림 | 토큰당 10회/분 | 429 | `routes/notifications.ts` |〃 (B 트랙) |
| 워커 타임아웃 | job당 10분 | `failed` 처리 | `worker.py` `asyncio.wait_for` | 행 걸린 ffmpeg/whisper가 워커를 영구 점유하는 것 방지 |
| 소유권/상태 | 내 소유 + `ready`만 편집 가능 | 403 | `edit-job.service.ts` | 데이터 무결성 |

## 2. 채택하지 않은 초기 플랜안

아래 표는 **초기 기획안이며 채택된 정책이 아니다**. 월 3편 모델은 제거했고,
스토리지 용량 한도(Free 5GB)는 [snap-source-of-truth.md](./snap-source-of-truth.md) §6에서
별도로 결정했다. 이를 현재 또는 향후 플랜 계약으로 사용하지 않는다.

초기 기획안(착수 시점 계획서 §Phase 8, `billing.service.ts`의 `features` 문구):

| | Free (₩0) | Standard (₩9,900) | Premium (₩24,900) |
|---|---|---|---|
| 편집 횟수 | 월 3편 | 무제한 | 무제한 |
| 해상도 | 720p | 1080p | 4K |
| 워터마크 | 강제 삽입 | 없음 | 없음 + 추가 기능 |

결정 당시 코드 상태:

- **월 3편**: 구현되어 있었으나 **2026-08-05 임시 제거** (아래 §3). 이력은 git에 있음
  (`edit-job.service.ts`의 `FREE_MONTHLY_LIMIT`, 제거 커밋 참조).
- **해상도 차등**: 미구현. 워커가 플랜과 무관하게 1080x1920으로 렌더링. 큐 페이로드에
  plan이 전달되지 않아 워커는 요청자 플랜을 알 수 없다.
- **워터마크**: 미구현 (같은 이유).
- `GET /billing/plans`의 `features` 배열은 FE 표시용 문구일 뿐 백엔드가 집행하지 않았다.
  실제 동작과 불일치하므로 새 정책을 구현할 때 함께 갱신해야 하는 영향 범위다.

## 3. 월 3편 제한을 임시 제거한 이유

- 해상도/워터마크가 미구현이라 어차피 **플랜 차등이 일관되게 동작하지 않는 상태**였음.
- 결제(B 트랙)와 편집 엔진(A 트랙)에 걸친 기획이라 각자 부분 구현하면 어긋남.
- 기존 구현에 기획 판단이 필요한 논점들이 있었음 (§4). 어설픈 정책으로 개발·검증만
  방해(실검증 중 반복 403)되어, 기획 확정까지 제외하기로 결정.

## 4. 결정 당시 확인한 정책 논점

아래는 월 3편 제한을 그대로 복원하지 않기로 한 근거다. 후속 정책의 요구사항 목록이나
진행 상태로 사용하지 않는다. 실제로 결정할 항목은 [backlog.md](../backlog.md) A-2가 원천이다.

기존 구현(`git log -S FREE_MONTHLY_LIMIT`)의 동작에서 확인한 논점:

1. **차감 시점** — 기존: `edit_jobs` 레코드 생성 시점 카운트. 그래서 **실패한 편집도
   차감**됐다 (워커 버그로 3회 실패하면 그 달 편집 불가). 성공 시점 차감으로 바꾸면
   사용자에게 유리하지만, 고의 취소/타임아웃 어뷰징 여지. → 절충안: `status != 'failed'`
   만 카운트 or 실패 시 환급.
2. **리셋 기준** — 기존: **UTC 월초** (`Date.UTC(y, m, 1)`) = 한국 시간 매월 1일 09:00.
   KST 자정으로 할지, 가입일 기준 rolling 30일로 할지.
3. **"1편"의 정의** — 기존: `POST /edit-jobs` 1회 = 1편 (클립 1개든 10개든 동일).
   클립 수·영상 길이 가중치를 둘지.
4. **해상도 차등과 세로 규격의 충돌** — 2026-08-04에 출력이 세로 1080x1920으로 확정됨.
   "Free 720p"를 세로로 해석하면 720x1280인지, 단변 720 기준인지 정의 필요.
5. **워터마크 스펙** — 위치/크기/로고 에셋. `editor.py`에 overlay 한 단계 추가로 구현 가능.
6. **전달 경로** — 해상도/워터마크를 강제하려면 큐 페이로드(`EditJobData`)에 plan을 실어
   워커에 전달해야 한다 (`subtitles` 옵션과 같은 패턴, 2026-08-04 커밋 참조).

## 5. 새 플랜 정책의 예상 영향 범위

> 아래는 영향 범위를 설명하기 위한 목록이며 완료 상태를 관리하지 않는다.

- `apps/api/src/services/edit-job.service.ts` — 크레딧 차감·차단·실패 시 환급 규칙

- 통합 테스트 — 크레딧 기대값, 잔액 부족 차단, 구매·플랜 변경 후 해제, 실패 시 차감·환급
