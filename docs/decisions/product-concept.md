## 1. 왜 다시 정했나 — 필름 은유를 걷어낸 이유

이전 기획은 "필름을 찍고 → 하루가 끝나면 현상한다"는 은유 위에 서 있었고, 은유가 제품 규칙까지 지배했다.

- **하루 1롤 강제** — 여러 날에 걸친 영상, 주제별 영상을 만들 수 없다.
- **미현상 블러** — 사용자가 방금 찍은 영상을 못 본다. 은유를 위해 기능을 뺐다.
- **지연 현상** — 만들고 싶을 때 못 만든다. 하루가 끝나야 한다.
- **AI가 안 보인다** — "현상" 의식 뒤에 숨어, AI 제품인지 필름 감성 아카이브 앱인지 구분되지 않는다.

원래 의도는 AI 기반 숏폼 브이로그 제작 앱이었으므로 은유를 걷어냈다.

- **다시 들이지 않는 것**: 하루 1롤 · 현상 의식 · 미현상 블러 · 필름 그레인·퍼포레이션·edge print 같은
  "필름임을 주장하는" 장식 · 12컷 목표 · `보관함` 이라는 탭 이름 · 지오펜스 기반 자동 수집.
- **남긴 것**: 짧은 촬영 · 원본은 불변이고 조합은 별도(N:M, §5) · 촬영 리마인더 · 푸시/위치 알림 인프라 ·
  인증/설정. 영상이 놓이는 바탕을 어둡게 두는 것도 남겼다 — 영상 앱에서 어두운 바탕은 은유가 아니라 기능이다
  (라이트 테마에서도 영상 바탕은 어둡다).

## 2. 제품 한 줄 정의

> **짧게 여러 번 찍어두면, AI가 한 편의 숏폼 브이로그로 만들어 주는 앱.**

두 개의 명사로 제품이 설명된다: **재료**(스냅)와 **완성작**(무비).

## 3. 방향 — 스튜디오(작업대형)

홈은 **내 작업대**다. 모아 둔 재료와 진행 중인 무비가 늘 여기 놓여 있고, 앱을 다시 열면 하던 작업을 이어서 한다.

**전제**: 사용자는 결과물을 자기 손으로 통제하고 싶어 한다. AI는 주인공이 아니라 마지막에 붙는 강력한 도구다.

**비교한 세 방향**(2026-07-28, 홈의 성격만 달리한 프로토타입): `오늘`(AI 제안형) · `스튜디오`(작업대형) ·
`레시피`(의도 우선형). 비교 문서의 추천은 레시피였고 **채택은 스튜디오**다. 뒤집은 근거는 비교 문서 자신의
단서였다 — 레시피는 레시피 카탈로그를 상시 운영해야 성립하는데 그걸 감당할 사람이 없고, 스튜디오는 운영 비용이
0에 가깝고 백엔드도 합성 작업 하나로 출발할 수 있었다.

**나머지 두 방향은 기각이 아니라 뒤로 미룬 것이다.** 세 방향은 배타적이지 않고 단계로 놓을 수 있다. 레시피
카탈로그 운영은 운영할 사람이 생겼을 때만 착수한다. 레시피에서 운영 부담이 거의 없는 부분만 먼저 가져온 것이
**슬롯 템플릿**이다 — 슬롯 이름은 사람에게 주는 촬영 지시일 뿐 채워진 스냅의 내용에 대한 주장이 아니다(TPL-1).
카탈로그를 서버로 옮긴 이유는 [movie-templates.md](../../apps/mobile/docs/features/movie-templates.md#catalog-policy)
의 "Catalog policy".

무비를 시작하는 길은 그래서 **두 갈래**다 — 스냅을 직접 골라 시작하거나 템플릿으로 시작한다. 둘은 서로를
소모하지 않고 같은 무비 화면에서 만난다(MOV-3).

**감수한 것**

- 첫 무비까지 탭이 많다 — 작업대형은 6–8회로, 제안형(2회)·레시피형(3–4회)보다 길고 이탈 지점이 많다.
- AI가 도구로 밀려나 제품 차별점이 흐려질 수 있다. 차별화는 **재료 관리 경험**이 진다.
- 촬영을 부르는 힘이 약하다. 자동 수집을 버렸으므로 촬영을 부르는 장치는 촬영 리마인더(지금은 준비 중 —
  [me.md](../../apps/mobile/docs/features/me.md))와 템플릿의 빈 슬롯 `지금 찍기` 다.

## 4. 이름 — 고른 이유와 기각한 이름

화면에서 쓰는 어휘와 금지어의 원천은 [ux-writing.md](../../apps/mobile/docs/ux/ux-writing.md) 다. 여기에는
이름을 고른 이유만 둔다.

| 개념 | 이름 | 이유 |
| --- | --- | --- |
| 짧은 원본 조각 | **스냅** | 브랜드명 Snaply 와 직결된다. |
| AI가 만든 결과물 | **무비** | "스냅↔무비 = 재료↔완성작" 대비가 바로 읽히고 단위로도 자연스럽다("무비 3편"). 기각: `릴`(인스타 릴스와 충돌), `브이로그`(장르명이라 단위로 어색), `에피소드`(연재물 느낌), `컷`(스냅과 혼동). |
| 무비 안의 한 조각 | **컷** | 스냅이 무비에 들어가면 컷이 된다. |
| 모으는 중인 스냅 묶음 | **초안 무비** | 고른 스냅은 곧바로 초안 무비가 된다. 별도 바구니를 두지 않는 이유는 [studio.md](../../apps/mobile/docs/features/studio.md#why-there-is-no-basket-between-a-pick-and-a-movie). |
| 홈 | **스튜디오** | 홈의 이름은 홈이 담는 것에서 나온다. |
| 프로필 + 설정 | **나** | 한 글자이고, `마이`·`프로필`보다 짧으며 한국어 앱 관례에 맞다. |
| 촬영 | 탭바 가운데 버튼 | 탭이 아니라 액션이다. 4탭 + 가운데 버튼 = 5슬롯(틱톡·인스타 관례)이라 어느 탭에서든 찍을 수 있다. |

**"폼"은 쓰지 않는다.** 어원(필름)이 걷어낸 은유에 묶여 있고, 한국어에서 "폼"은 form(양식)으로 먼저 읽힌다.

## 5. 모델 — 원본과 조합을 나눈다

- **스냅은 불변 원본, 무비는 스냅을 참조하는 조합이다(N:M).** 순서와 트림은 무비마다 따로 가진다 — 같은 스냅을
  두 무비가 다르게 자를 수 있다(MOV-1).
- **무비 하나가 멤버십과 결과물을 모두 가진다.** 사용자가 같은 객체를 편집하고 생성하므로, 멤버십(롤)과 현상
  결과(릴)를 나누던 이전 모델을 하나로 합쳤다.
- **`failed` 는 1급 상태다.** AI 작업은 실패하고, 사용자는 "아직 안 돌렸다"와 "망가졌다"를 구분할 수 있어야 한다.
- **룩(스타일)은 무비가 가진다.** 찍을 때 조각마다 고르지 않고, 무비 화면에서 전체를 보면서 고른다 — 스냅에는
  무드 옵션이 없다.

## 6. 무비 화면 — 한 화면에서 만들고, 보고, 고친다

- **무비는 상태가 무엇이든 한 화면(`/movie/[id]`)에서 연다.** 완성본을 보는 것과 고치는 것은 같은 방문이고,
  라우트를 둘로 나누면 같은 컷 목록을 고칠 수 있는 곳이 둘이 된다.
- **편집은 실행 밖에서 한다**(MOV-4). 기각한 두 형태:
  - 생성 전 3단계 위저드(조립 → 스타일 → 생성) — 한 객체를 세 화면으로 쪼갰다.
  - 그 반작용인 "수정은 생성 이후에만" — 사용자가 아직 확정하지 않은 구성에 비용을 치르게 했다.

  생성이 유료 원격 작업이 된 뒤로는 **구성을 먼저 확정하고 실행하는 것**이 규칙이다.
- **순서 고정 — 컷 순서의 주인을 무비가 기억한다**(`user` | `ai`). 스냅을 골라 만든 무비는 `user`, 템플릿으로
  만든 무비는 `ai` 다. 사용자가 손으로 순서를 바꾸면 그 순간 `user` 가 된다 — 옮겼다는 것이 곧 고정하겠다는
  뜻이므로 스위치를 먼저 찾게 하지 않는다. 스위치는 순서를 다시 AI에게 넘겨주기 위해 있고, 트림은 재배치가 아니다.
  `user` 인 무비의 순서와 트림은 생성이 건드리지 않는다. 지금 "AI가 배치한다"의 실체는 촬영 시각 순 정렬이다
  ([movie.md](../../apps/mobile/docs/features/movie.md)).
