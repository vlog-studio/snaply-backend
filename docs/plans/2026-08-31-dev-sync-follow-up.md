## 1. 반드시 해야 하는 일 — 트랙별

### T1. 웹훅용 HTTPS 고정 도메인 (backlog D-1 · B-1)

**먼저 정할 것**: "웹훅 연동"이 무엇을 가리키는지. 현행 릴스 게시·틱톡 업로드 모두 **폴링**으로
완료를 확인하고 웹훅이 필요 없다. 후보는 ① Meta 콘솔이 요구하는 등록 핸드셰이크(이미 구현),
② 틱톡 게시 상태 콜백(라우트 없음), ③ RevenueCat·AdMob 결제 웹훅(라우트 있음, 도메인만 대기).
셋 다 **고정 도메인이 전제**라 도메인 작업은 무엇이든 필요하다.

**순서**
1. 사내 AWS 계정에서 보유 도메인·Route 53 호스팅 영역 파악 → `api.<도메인>` 서브도메인 할당.
2. ACM 인증서 발급. 종단은 B-1 배포 타깃에 따라 ALB 또는 CloudFront — **B-1 결정을 같이 끝낸다.**
   도메인만 있고 뒤에 서버가 없으면 콜백을 받을 수 없다.
3. 운영 환경변수 확정: `API_BASE_URL` · `INSTAGRAM_REDIRECT_URI` · `TIKTOK_REDIRECT_URI` ·
   `CLOUDFRONT_DOMAIN` / `S3_PUBLIC_ENDPOINT`. 값은 배포 플랫폼 시크릿으로 주입한다
   ([decisions/env-management.md](../decisions/env-management.md)).
4. 인스타·틱톡 콘솔에 리디렉션 URI·웹훅 URL 재등록, URL prefix 소유권 검증 재등록(D-3).
5. 틱톡 웹훅이 필요하다고 결론나면: `routes/sns-webhook.ts`에 서명 검증 + `SnsUpload` 상태 갱신
   라우트 추가 → 계약(`contract/sns.ts`)·`openapi.json`·`api-spec.md`·테스트 갱신.
6. 도메인이 생기면 같은 도메인으로 Meta 검수 URL 2개(C-5)와 결제 웹훅(C-1·C-6) 검증을 잇는다.

**완료 조건**: 운영 도메인에서 OAuth 복귀·(필요한) 웹훅 수신이 한 번 통과하고 D-1을 닫는다.

### T2. 영상·프로젝트·결과물 생애주기 결정 (backlog A-1 ⑥) ★ 다른 트랙의 입력

회의 제안(15일 · 로컬 삭제 · 내보내기 후 삭제)은 현행 결정 두 편과 충돌한다. **결정 문서 한 편**
(`decisions/content-lifecycle.md` 가칭)으로 세 축을 한 번에 정한다. 각 축의 선택지와 비용:

| 축 | 회의안 | 현행 | 판단에 필요한 것 |
|---|---|---|---|
| 영상 보관 | 15일 후 만료 | 만료 없음, Free 2GB 한도 | 만료가 한도를 **대체**하는지 **병행**인지. 대체하면 SNAP-9 집행 설계가 사라져 단순해지고, 병행하면 두 규칙을 사용자에게 설명해야 한다 |
| 로컬 사본 | 업로드 성공 시 삭제 | 로컬이 원천 | **서버 원천 전환 1~3단계**([snap-source-of-truth](../decisions/snap-source-of-truth.md) §5)가 끝나기 전에 로컬을 지우면 재생 불가·복구 불가다. 렌디션(2단계) 없이는 크로스 플랫폼 재생도 깨진다 |
| 프로젝트·결과물 | 내보내기 완료 시 프로젝트 삭제, 결과물은 다운로드/SNS 후 삭제 | 구성 영구 보관 + 결과물 30일 + 무료 재생성 | 삭제로 가면 "다시 만들기"(MOV-4 재생성 UX)와 "만료 무비 무료 재생성" 약속이 사라진다. 대신 보관 축 구독(A-2)의 근거가 약해지고 A-7 에셋 영구 라이선스 논의가 닫힌다 |

**권장**: 로컬 삭제는 **서버 원천 전환 완료 뒤로 조건부 연기**하고, 결과물 삭제는 "사용자가 내보내기
화면에서 진행하면 앱 로컬의 프로젝트를 정리한다"로 좁혀 **서버 측 MOV-14·MOV-16은 유지**하는
혼합안을 1안으로 올린다. 이유는 이미 결제·보관 정책 3편이 30일 보관을 전제로 확정돼 있어, 서버 삭제로
바꾸면 A-2 구독 상품 설계까지 되돌아가야 하기 때문이다. 최종 선택은 회의의 몫이다.

**결정 후 구현(채택안에 따라 일부만)**: spec(SNAP-9·SNAP-11·MOV-14·MOV-16) 갱신 → `Video.expiresAt`
또는 `Movie` 만료 컬럼 마이그레이션 → GC 배치(E-3 경로 공용) → 앱 로컬 정리 규칙
(`apps/mobile/docs/features/snaps.md`·`movie.md`) → 만료 안내 알림(FCM 전환은 A-1 선행 조건).

### T3. 프로젝트(Movie) 서버 엔티티와 내보내기 동선 (backlog A-1 ①~⑤)

회의의 `project` = 결정된 **`Movie`**, `vlog` = 렌더 결과물. 구성 요소 `video · order · effect ·
sticker · bgm · subtitle`은 `editSpec` v3 의 층과 1:1로 대응하므로 **프로젝트 필드를 따로 설계하지 않고
v3 스펙을 프로젝트 본문으로 쓴다**(A-7 부착 지점 결정 = "Movie export 에 붙인다").

**순서**
1. A-1 남은 판단 ①~⑤ 확정(클립 순서 기본값 · 재내보내기 누적/교체 · 삭제 시 참조 처리 ·
   자동 그룹핑 범위 · `POST /edit-jobs` 폐기 시점) — T2 와 같은 회의에서.
2. `Movie`(+ `MovieClip`) 스키마 — 서버 원천 4단계. `schema.prisma`는 공유 파일이라
   [team.md](../team.md) §2 절차.
3. 계약 `contract/movies.ts` 신설: CRUD + `POST /movies/:id/export`(내부적으로 EditJob 생성,
   크레딧 예약 로직 재사용). `openapi.json` 재생성, `api-spec.md`, 테스트.
4. 앱: `snaply.movies` 로컬 저장소 → 서버 Movie 동기화. "목록 → 내보내기 바로" 동선은
   [`movie.md`](../../apps/mobile/docs/features/movie.md)의 ready/draft 화면에 **내보내기 진입 버튼**을
   추가하는 앱 변경이고, 내보내기 화면(다운로드 / SNS 연동 선택)은 새 기능 문서가 필요하다.
5. 구간 질문(#9)은 회신만: 컷마다 `startMs`/`endMs`를 이미 받는다.

### T4. BGM — AI 생성 음원 법적 검토 → 조달 → `bgm_tracks` (backlog A-7 · E-5)

**법적 검토 체크 항목**(어느 조달 경로든 동일): ① 상업 이용 허용 ② **최종 사용자의 소셜 업로드**
허용 ③ Content ID 클레임 면제 또는 화이트리스트 ④ 생성물의 저작권 귀속(AI 생성물은 국가별로
저작권 불성립 가능 → 제3자 재사용 위험 평가) ⑤ 만료 후 기존 저작물 사용 유지 조항(T2 에서 재생성을
유지할 경우만) ⑥ 모델 학습 데이터 출처에 대한 서비스 측 면책 범위.

**순서**: 후보 서비스(AI 생성 2~3곳 + 상업 라이선스 3곳) 약관을 위 6항으로 표 비교 →
`decisions/bgm-sourcing.md` → 15~20트랙 확보 → `bgm_tracks` 스키마(무드 태그·BPM·비트 그리드) →
트랙 ID를 `renderSpec`에 고정해 E-5(무작위 선택) 해소 → F 항목 "실BGM 기준 whisper 재확인".

### T5. 자막 (backlog A-7)

결정만 필요하다. 선택지는 ① 현행 소프트 자막 유지(SNS 업로드 시 유실 안내 유지) ② ASS/libass 번인
전환(단어 단위 애니메이션 가능, FE 계약 변경·재인코딩 1회 증가). 결정 전까지 구현은 없다. 번인으로
가면 MOV-9 spec → `api-spec.md` 안내 문구 → 워커 순서로 바꾼다.

### T6. 스티커·에셋 확보와 관리자 페이지 (backlog A-7 신규)

관리자 인증·권한 모델이 전혀 없으므로 **관리자 페이지를 먼저 만들지 않는다.** 단계를 나눈다.

1. **에셋 조달·라이선스**: 스톡 다수가 "파생물 생성 앱 포함"을 금지하므로 디자이너 커미션(40~60종 ·
   3~4스타일) 여부를 A-7 에서 결정. 라이선스 조항은 T4 ⑤와 같은 영구 사용권 이슈를 공유한다.
2. **매니페스트 저장**: kickoff §1.2 C·D 로 설계가 끝난 스티커 팩 매니페스트를 저장소(또는 S3 버킷)에
   두고 **시드 스크립트로 등록**한다. 이 단계만으로 파이프라인 검증이 가능하다.
3. **관리자 페이지**: 팩 등록·상태 전이(`experimental → active → deprecated`)·미리보기가 필요해질 때
   `decisions/admin-console.md`로 범위·인증(Supabase 커스텀 클레임 `role=admin` 등)·호스팅을 정한 뒤
   착수. 백엔드에는 `/admin/*` 라우트와 관리자 가드가 새로 필요하다.

### T7. 위치 정보 (backlog A-4)

프라이버시·약관 검토가 선행이고 이 회의로 바뀐 것은 없다. 검토가 끝나 저장으로 결정되면
[snap-source-of-truth](../decisions/snap-source-of-truth.md) §4 의 1단계 스키마(`place` 컬럼)와
`POST /videos` 계약을 같은 변경에서 갱신한다. 기기 권한 거부 시 `null` 허용이 기본이다.

### T8. AI 추천 프로젝트 (backlog A-6)

"프로젝트 자동 구성 추천"이 템플릿 추천(A-6)의 확장인지 별개 기능인지부터 정의한다. 확장이면
A-6 후속 후보(`다른 조합`·라이브러리 기준 정렬)로 흡수하고, 별개면 결정 문서를 새로 쓴다.
T3 의 `Movie` 서버 엔티티가 있어야 서버가 프로젝트를 제안할 수 있으므로 **T3 이후**다.

### T9. 확인만 필요한 것

- 틱톡 받은함 실물 도착(C-2)이 회의의 "정상 동작 확인"에 포함됐는지 참석자 확인 → 포함이면 C-2 닫기.
- 내보내기 구간 지원(#9) 회신.

## 2. 선후관계와 착수 순서

```text
T2 생애주기 결정 ──┬──▶ T3 Movie 엔티티·내보내기 ──▶ T8 AI 추천 프로젝트
                   └──▶ (로컬 삭제는 서버 원천 1~3단계 완료 후)
T1 도메인(B-1 배포 타깃과 함께) ──▶ 웹훅·검수·결제 검증(C-1·C-5·C-6·D-3)
T4 BGM 법적 검토 ──▶ 조달 ──▶ bgm_tracks ──▶ E-5 해소
T6 에셋 조달 ──▶ 매니페스트 시드 ──▶ (필요 시) 관리자 페이지
T5 자막 · T7 위치 · T9 확인 : 독립
```
